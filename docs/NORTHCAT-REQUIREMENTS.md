## 3. Ключевые решения

### 3.1 Биллинг: что считается удачной генерацией

Кредит списывается ТОЛЬКО при выполнении всех условий (иначе операция бесплатна):

1. API вернул изображение (не текст-отказ, не ошибка/таймаут)
2. Нет safety-block
3. Выход прошёл проверки качества: не пустой, размер ≥ минимума, не однотонный (дисперсия пикселей выше порога), для переноса — соразмерен входу

- Брак → авто-повтор бесплатно, максимум 3 попытки на операцию, потом стоп
- 1 кредит = 1 успешная картинка. Повтор той же операции = новый кредит
- Лимиты на аккаунт: N/мин и N/день даже при наличии кредитов (антифрод)
- Списание на сервере, после проверок

### 3.2 Подтверждения перед этапами

- Перед ИИ-операцией — окно: превью входа + описание + стоимость
- Деструктивные действия — отдельное подтверждение
- Чек-лист готовности (фото/эскиз/зона) разблокирует кнопку
- Валидация входа до отправки: формат, размер, разрешение (+ предупреждения о возможном плохом результате)

### Детализация ключевых задач

**#31 Аккаунты (M1)** — на сайте сразу 3 способа:
- Google OAuth 2.0 (кнопка «Войти через Google»)
- Telegram Login Widget (на сайте) + авто-вход по `initData` в Mini App
- Passkey / WebAuthn (регистрация и вход)
- единый `user`, httpOnly-сессия, привязка способов по email/tg_id

**#33 Прокси Gemini (M3) + «удачная генерация» (§3.1)** — кредит списывается только если:
1. вернулось изображение (не текст/ошибка/таймаут)
2. нет safety-block
3. выход прошёл проверки (не пустой, размер ≥ мин, не однотонный по дисперсии, соразмерность для transfer)
- брак → бесплатный авто-ретрай ≤3 → стоп
- идемпотентность по request-id (двойной клик не списывает дважды)
- лимиты N/мин и N/день даже при балансе

**#38 Google Drive (M5)** — папка данных на аккаунте владельца:
- OAuth владельца (refresh-token) или сервис-аккаунт
- `northcat-data/users/{id}/uploads|results`, `sketches/`, `tmp/`
- в БД `drive_file_id`, отдача прокси-стримом; сжатие; чистка tmp; резерв S3

**#41 Кешбек (M8)** — баллы за покупки:
- админ в боте: «клиент X, сумма Y» → начисление баллов (% настраивается)
- `points_ledger` (приход/расход), баллы тратятся на генерации/скидки
- источник сумм — услуги/товары (`PRODUCTS`, прайс из `data.js`)

**#37 Админка в ТГ (M10)** — расширение текущего `/setup`:
- коды (создать/список/отозвать), пользователи (баланс, начислить/списать, бан/лимиты)
- кешбек, статистика (генерации, ошибки, расход ключа), рассылки, логи
