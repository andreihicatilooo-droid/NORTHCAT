# 📐 Шаблоны и чек-листы

Быстрые стартеры для разных типов задач.

## 🎯 Шаблон: Новая задача в бэклог

Используй это когда добавляешь новую задачу:

```markdown
## [Тип] Название задачи

**Приоритет:** P1/P2/P3/P4
**Deadline:** ДД.МММ или "нет"
**Зависит от:** [список задач или "нет"]
**Блокирует:** [что блокирует или "ничего"]
**Описание:** 1-2 предложения, что это и почему важно

**Subtasks:**
- [ ] Substep 1
- [ ] Substep 2
- [ ] Substep 3

**Успех когда:** описание критериев "done"

**Примечания:** любые контексты или ссылки
```

### Пример (скопируй и заполни):

```markdown
## [Feature] Интеграция платежей Stripe

**Приоритет:** P2
**Deadline:** 15.08
**Зависит от:** Website API ready, Database schema
**Блокирует:** Launch production
**Описание:** Добавить возможность онлайн-платежей за услуги салона

**Subtasks:**
- [ ] Зарегистрировать Stripe account
- [ ] Написать API endpoints (/create-payment, /confirm-payment)
- [ ] Интегрировать в Website checkout page
- [ ] Тестирование (dev mode)
- [ ] Production setup

**Успех когда:** Можно оплатить услугу через сайт, деньги приходят в Stripe

**Примечания:** 
- Stripe docs: https://stripe.com/docs/payments
- LuxHost может давать свой payment solution
```

## 🧠 Шаблон: Идея в ideas.md

```markdown
## [Идея] Название идеи

- **Описание**: одна строка в чем суть
- **Почему важно**: 1-2 причины
- **Примерная сложность**: LOW / MEDIUM / HIGH
- **Связи**: [какие задачи/проекты затрагивает]
- **Статус**: Сырая идея / Обсуждение / Готова в backlog
```

### Пример:

```markdown
## [Идея] Система горячих клавиш для KB

- **Описание**: Быстрые сочетания клавиш (Cmd+K) для поиска и навигации по KB
- **Почему важно**: Экономит время при работе с множеством файлов
- **Примерная сложность**: MEDIUM
- **Связи**: Knowledge Base, AI-агенты, улучшение UX
- **Статус**: Сырая идея (28.05 from slack)
```

## ❓ Шаблон: Вопрос в questions.md

```markdown
## [Домен] Формулировка вопроса?

**Контекст**: почему этот вопрос актуален сейчас

**Варианты ответов:**
1. Вариант A (плюсы/минусы)
2. Вариант B (плюсы/минусы)
3. Вариант C (плюсы/минусы)

**Нужно решить до:** DD.MM

**Источник информации:** где искать ответ (docs, люди, исследование)
```

### Пример:

```markdown
## [Архитектура] Монорепо vs микросервисы?

**Контекст**: Проект растет, нужно решить как структурировать код для salon-api и website

**Варианты ответов:**
1. Монорепо (единый repo)
   - ✅ Проще управлять зависимостями
   - ✅ Един CI/CD
   - ❌ Сложнее при отдельных deployments
   
2. Микросервисы (отдельные repos)
   - ✅ Независимые deployments
   - ✅ Масштабируемость
   - ❌ Сложнее с синхронизацией

**Нужно решить до:** 20.06

**Источник информации:** 
- Посмотреть как структурирован NORTHCAT сейчас
- Прочитать best practices для Next.js + Node.js
- Посоветоваться с Claude
```

## ✅ Чек-лист: Завершение спринта (каждую пятницу)

```markdown
## Спринт Review - [неделя]

### Завершенные задачи
- [ ] Задача 1 → перемещена в completed.md
- [ ] Задача 2 → перемещена в completed.md
- [ ] ...

### Незавершенные задачи
- [ ] Вернуть в backlog (с объяснением почему)
- [ ] Спросить Claude помощь если нужно
- [ ] Обновить приоритеты

### Новые идеи из недели
- [ ] Добавить в ideas.md
- [ ] Организовать если нужно

### Планирование следующего спринта
- [ ] Прочитать backlog.md
- [ ] Выбрать 5 max задач
- [ ] Скопировать в current-sprint.md

### Здоровье проекта
- [ ] Mood: Как ты себя чувствуешь? (😊/😐/😠)
- [ ] Блокеры: Что мешает?
- [ ] Выгорание: Нужно ли уменьшить нагрузку?
```

## 🏗️ Чек-лист: Новая техническая задача

```markdown
## Tech Task: [Название]

### 📋 Четкость
- [ ] Написана в current-sprint.md с subtasks
- [ ] Есть критерии "done"
- [ ] Зависимости понятны

### 💻 Подготовка
- [ ] Нужные tools установлены (npm, docker, etc)
- [ ] Docs / примеры найдены
- [ ] Нужно ли обсуждать с Claude?

### 🚀 Во время работы
- [ ] Обновляешь статус в current-sprint.md
- [ ] Пишешь questions если застрял
- [ ] Коммитишь регулярно

### ✅ При завершении
- [ ] Код готов и протестирован
- [ ] Документация обновлена
- [ ] Перемещаешь в completed.md
- [ ] Создаешь commit с описанием
```

## 🎨 Чек-лист: Дизайн задача

```markdown
## Design Task: [Название]

### 🎯 Требования
- [ ] Понимаешь vision (вдохновение, reference images)
- [ ] Знаешь цветовую палитру (hot pink #f4587e, dark #0c120e)
- [ ] Есть размеры/форматы (mobile? desktop? print?)

### ✏️ Процесс
- [ ] Создан новый design в Canva
- [ ] Несколько вариантов готово
- [ ] Получено feedback (если нужно)

### 🎨 Финал
- [ ] Выбран финальный вариант
- [ ] Экспортирован в нужных форматах (PNG, SVG, PDF)
- [ ] Загружен в `/design/` или Canva folder

### 📦 Архив
- [ ] Ссылка на Canva design добавлена в docs/RESOURCES_LINKS.md
- [ ] Перемещено в completed.md
```

## 🤖 Чек-лист: AI-агент команда

```markdown
## AI Agent Task: [Название]

### 📝 Инструкция для Claude
- [ ] Написано что делать ясно (не "помоги", а "организуй ideas.md")
- [ ] Дан контекст (какие файлы читать)
- [ ] Дано что на выходе ожидается

### 🔄 Выполнение
- [ ] Claude обновил необходимые файлы
- [ ] Результат соответствует ожиданиям
- [ ] Если нужно уточнение - спросил

### ✅ Результат
- [ ] Файлы обновлены верно
- [ ] Все changes закоммичены
- [ ] Обновлен completed.md
```

## 🔗 Связь между файлами

```
ideas.md          → Идеи скидываешь сюда (QUICK INPUT)
     ↓ (Claude организует)
backlog.md        → Идея становится задачей с приоритетом
     ↓ (В понедельник)
current-sprint.md → Выбираешь max 5 для работы
     ↓ (В конце недели)
completed.md      → Готовое архивируется (PROGRESS!)

questions.md      ← Вопросы которые встретились
     ↓ (Ответ найден)
docs/decisions/   → Решение документируется

connections.md    ← Зависимости между проектами
                    (читаешь перед планированием)
```
